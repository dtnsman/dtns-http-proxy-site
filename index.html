01 — 概览

把「本地能跑」
变成「公网可用」。

大多数内网服务并不缺功能，缺的是一个稳定、可寻址的公网入口。dtns.http-proxy 用一条常驻 WebSocket 把内网节点连到公网边缘：请求按域名分发，响应沿原路返回——不需要公网 IP，也不需要动路由器。

01

没有公网 IP？

客户端主动向外建立 WSS 长连接。NAT、防火墙、动态 IP 之后的内网机器，也能被稳定访问。

多个本地服务？

03 — 能力

不只转发页面，
也转发「连接」。

很多穿透工具能打开一个网页，却在 WebSocket 或事件流上退化成轮询。dtns.http-proxy 把这些通道当作一等公民。

ROUTING

Host 即路由

每条隧道绑定一个域名。请求按 Host 精确匹配，多服务共用一个客户端也不会串线。

WEBSOCKET

WebSocket 全双工

升级握手同样走隧道；101 之后 text / binary 帧双向透传，帧类型用标志位无损保留。

STREAM

SSE 与流式响应

text/event-stream 增量透传。大响应按块下发，通过信用窗口控制节奏，不必整包缓冲。

PROTOCOL

DTNS 二进制协议

4 字节魔数 + 固定头 + 纯二进制负载，没有 Base64 膨胀；v2 用双字节状态码修复 4xx/5xx。

BACKPRESSURE

双向背压

浏览器侧与隧道侧各自设置高低水位（256 KB / 64 KB），慢消费者不会把内存吃满。

RESILIENCE

自愈连接

30 秒心跳、线性退避重连、健康校验失败后自动重连并全量重新注册隧道。

04 — 协议

为「原样转发」
设计的帧格式。

DTNS 协议不追求通用，只解决一件事：让 HTTP 与 WebSocket 在一条长连接里高效、无损地通过。

DTNS4 B
VER1 B
TYPE2 B
FLAGS2 B
LEN4 B
PAYLOADN B

固定头 13 字节；LEN 只描述负载长度。请求体与响应体直接以 Buffer 传输，不做文本化。

register_tunnel 0x0001 http_request 0x0105 http_response 0x0004 websocket_data 0x000D stream_chunk 0x0021 heartbeat 0x0003 共 30+ 种

几个关键约束

  • 零 Base64。响应体、请求体、WebSocket 帧都是原始字节，避免 33% 的编码开销。
  • 多值头无损。头部按数组编码，多个 Set-Cookie 不会被逗号拼坏。
  • 帧类型显式。IS_BINARY 标志区分 WebSocket 的 text 与 binary 帧，不再靠 UTF-8 猜测。
  • 向后兼容。客户端读取服务端欢迎帧里的协议版本；旧服务端自动降级到 v1 或 JSON 分支。
FIX v1 → v2：状态码不再被截断

v1 的状态码只占 1 字节，401 会被截成 145，所有 4xx/5xx 接口在浏览器里都会变成非法状态。v2 改成 2 字节大端；遇到旧服务端时，客户端只把超范围响应切到 JSON 帧发送。

// protocol v1status = 401 & 0xff→ 145
// protocol v2writeUInt16BE(401)→ 401

05 — 上手

两台机器，三步跑通。

公网侧启动服务端，内网侧写一份 config.js 并启动客户端；域名解析与入口 TLS 交给 nginx。

公网服务器 · shell
cd server
npm install
node index.js

需要准备什么

一台有公网入口的服务器、一个指向它的域名，以及 nginx（或同类入口）把 80/443 转发到隧道服务端。

  • HTTP 代理监听 :18386
  • WebSocket 监听 :18385，路径 /tunnel
  • 入口层负责 TLS 与域名解析
server/config.js · 关键项
module.exports = {
  http:      { port: 18386, host: '0.0.0.0', domainBase: '.html.dtns.top' },
  websocket: { port: 18385, path: '/tunnel' },
  protocol:  { preferred: 'binary', binaryEnabled: true, version: 1 },
  clients:   { heartbeatTimeout: 60000, maxConnections: 1000 },
  streaming: { enabled: false, chunkSize: 262144, windowSize: 1048576 },
  limits:    { maxBodySize: 32 * 1024 * 1024 }
};
内网机器 · shell
cd client
npm install
node index.js

客户端做什么

读取 config.js，用唯一的 client.id 连接服务端，并把每条启用的隧道注册上去。

  • 主动外连，不需要入站端口
  • 心跳 30 秒，断线自动重连
  • 域名与本地端口的映射完全在本地配置
client/config.js · 最小示例
module.exports = {
  server: { wsServerUrl: 'wss://res2.dtns.top', wsPath: '/tunnel' },
  client: {
    id: process.env.CLIENT_ID || 'my-node-1',
    heartbeat: { interval: 30000 },
    reconnect: { enabled: true, interval: 5000, maxAttempts: 100000000 }
  },
  protocol: { preferred: 'binary', binaryEnabled: true, version: 1 },
  tunnels: [{
    id: 'web',
    domain: 'app.html.dtns.top',
    local: { host: '127.0.0.1', port: 3000, protocol: 'http' },
    enabled: true,
    description: '主 Web 应用'
  }]
};
任意机器 · shell
curl -I http://app.html.dtns.top/
# HTTP/2 200
# server: nginx
# content-type: text/html

看到 200 就通了

如果返回 404 No tunnel registered for domain，说明域名没有注册到任何客户端；检查 client.id、tunnels[].domain 与客户端日志。

  • WebSocket 回显测试：test/demo.js
  • 客户端日志会打印每条隧道的注册结果
  • 服务端仅监听 18385 / 18386，公网入口由 nginx 暴露

08 — 结构

代码不多，边界清楚。

客户端只负责「连上去、查表、转发」，服务端只负责「接住、查表、送回去」。协议层被单独抽出来，两端共用同一套编解码逻辑。

dtns.http-proxy/

│   ├── index.js            # 连接 / 注册 / 心跳 / 重连
│   ├── tunnel-manager.js   # 隧道表与请求分发
│   ├── http-proxy.js       # 本地转发 / WS / SSE / 流式

├── server/                 # 公网侧
│   ├── index.js            # 启动入口
│   ├── websocket-server.js # 连接与隧道注册
│   ├── proxy-server.js     # 域名路由 / 升级 / 背压
│   ├── protocol.js         # 与服务端一致的协议实现
│   └── config.js           # 服务端配置
├── test/                   # WebSocket 回显测试
└── website/                # 本站（静态页面 + 零依赖服务）

进程守护

现有部署用 forever 托管客户端；也可以交给 systemd、supervisor 或容器编排。

日志

客户端会打印隧道注册、转发失败与心跳统计；服务端按请求 ID 记录路由与状态码。

安全边界

只暴露需要暴露的服务，本地服务尽量绑定 127.0.0.1；入口层负责 TLS 与访问控制，请求体上限兜底大包。

09 — 问答

常见问题。

域名返回 404 No tunnel registered for domain？

说明请求已经到了隧道服务端，但 Host 没有匹配到任何已注册隧道。检查 client/config.js 里的域名拼写、客户端是否在线，以及客户端日志中的「隧道注册成功」。

为什么有的 4xx / 5xx 状态码显示不正常？

这是 v1 协议的单字节状态码限制：401 & 0xff = 145。使用 v2 协议即可无损传输；客户端连接旧服务端时会自动把超范围响应切到 JSON 帧。

WebSocket 连接建立后马上断开？

先确认本地服务本身能完成升级，再检查路径、子协议与 Origin。若本地框架校验 Host / Origin，可以在对应隧道上开启 rewriteHost / rewriteOrigin。

上传大文件被 413 拒绝？

服务端默认请求体上限是 32 MB。可以在 limits.maxBodySize 调整全局值，或用 maxBodySizeByDomain 为特定域名放宽。

客户端断线后需要手动重连吗？

不需要。客户端内置心跳与线性退避重连（上限 60 秒）；健康校验发现隧道未注册时，会主动重连并全量重新注册。

可以给隧道加访问控制吗？

建议在入口层（nginx basic auth、IP 白名单、OIDC 等）做访问控制。隧道配置里的 auth 是访问上游时附加的 Basic Auth，不是公网鉴权。
